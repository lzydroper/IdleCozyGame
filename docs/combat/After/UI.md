# UI 模块「将就」待完善清单

> 记录范围：`combat-ui`（战斗看板、战斗模态、事件流展示与区域选择）实现后的**已知取舍与未闭环项**。
> 语义：本文件只记录「能跑通、但为了先落地而做出的妥协」，不是 bug 清单；已通过的自动化测试与构建不代表这些点不需要后续打磨。
> 关联留档：底层引擎与规则的「将就」清单见同目录 `Turn.md` / `Ability.md` / `Effect.md` / `Buff.md` / `Entity.md` / `Offline.md`。

---

## 已落地（简短）

- **战斗信息流解耦展现（`battleEventPresentation.ts`）**：
  - 纯函数式事件展现管道：`formatBattleEvent` 统一输出各时机/细粒度事件的中文语义；
  - 自动静默内部管道钩子（如 `attackAfter`、计算层 `effectApplied`），提供 `isDisplayableEvent` 与 `displaySteps` 过滤机制，实现 UI 播放器与内部事件名零硬编码解耦。
- **全屏战斗视窗（`BattleModal.tsx`）**：
  - 6v6 对战棋盘阵列（虚线槽位 + 实体单位槽位）；
  - 动态受击闪烁、扣血、伤害/治疗飘字与阵亡变灰逻辑；
  - 统一基准时延除法变速（1x / 2x）与一键【跳过】；
  - 独立战斗场景严格提供【退出】（按失败结算并导致全员重伤），荒野遭遇战安全隐藏退出。
- **挂机监控看板（`IdleCombatWidget.tsx`）**：
  - 顶部区域/关卡标题、总场次/胜负统计、实时计时器与累计掉落物图标徽章；
  - 3 行固定高度事件流视窗，智能吸底滚动（用户向上查看历史时不强制滚底）；
  - 队列容量上限控制（50 行防内存膨胀）；
  - 点击【停止挂机】弹出标准汇总面板。
- **区域/关卡选择与诊断（`RegionSelectorModal.tsx` + `LevelBrowser.tsx`）**：
  - 主线阶梯式可见性过滤（已解锁 + 首个未解锁 + 测试区）；
  - 探索度/前置关卡/道具持有的结构化解锁诊断面板；
  - 「挑战」与「挂机」双模式平滑切换与关卡小方块网格。
- **招募结果弹窗（`SummonTab.tsx`）**：
  - 对齐全局标准弹窗规范（`UI_TOKENS.modalContainerStandard`，`h-[460px] max-h-[68vh]`）；
  - 4 列正方形（`aspect-square`）紧凑卡片排布与 `content-start` 防重叠。

## 待完善项

### 1. 战斗动画时长与倍速系统脱节

- **现状**：
  - `BattleModal` 中，受击红色闪烁（`isHit`）重置写死为 `250ms`；
  - 伤害/治疗浮动文字（`floatingDamages`）的清理写死为 `750ms`；
  - 而事件步进播放时延是由 `baseEventIntervalMs / speed` 动态计算的（例如 1x 为 500ms，2x 为 250ms）。
- **妥协点**：
  - 在 2x 倍速下，前一次攻击的飘字还没完全淡出（750ms），下一次攻击的飘字就已经生成，容易在短时间内堆叠重叠；若后续开放 4x/8x 极速模式，动画将严重脱节。
- **待完善**：
  - 将受击动画时长与飘字存活时长按 `speed` 等比缩放，或在 CSS 中绑定动态动画速率变量。

---

### 2. 挂机战斗的前台生命周期与结算时差

- **现状**：
  - `IdleCombatWidget` 内部在每场战斗开始时立即同步计算了完整 `simulateBattle` 与 `settleLevelBattle`，并将体力扣除和掉落数据直接写入全局 `GameState`；
  - 同时，将格式化事件推入 `queueRef`，通过前端 `setInterval` 逐行模拟播放给玩家看。
- **妥协点**：
  - **数据已落地 vs 视觉正播放的时差**：若玩家在一场战斗播到一半时点击【停止挂机】，实际上该场战斗的数据在后台已经全量写入完毕。
  - **组件卸载停顿**：挂机计时器挂载在 `IdleCombatWidget` 的 `useEffect` 上，玩家切换底部 Tab（如去避难所收菜）时组件卸载，挂机流停止推进，切回荒野后重新挂载。
- **待完善**：
  - 评估是否将挂机轮巡状态提升到 `GameContext` 或独立 Worker 中驱动，使切 Tab 时保持后台静默推进；或在 UI 上增加“正在收尾当前场次”的平滑停止提示。

---

### 3. 关卡与区域名称拼接在部分展示中存在重复前缀

- **现状**：
  - 部分区域配置中，`level.name` 填写的是完整全称（如 `废土边缘 · 游荡者`），而 `region.name` 为 `废土边缘`；
  - 战斗日志生成与弹窗标题部分写了 `${region.name} · ${level.name}`，导致文案呈现为 `【废土边缘 · 废土边缘 · 游荡者】`。
- **妥协点**：
  - 遵循指令“只改道具查表，名称先不管”，目前代码未对字符串做去前缀处理。
- **待完善**：
  - 方案 A（推荐）：在 `src/data/regions.ts` 根源清洗配置，将 `level.name` 统一精简为纯关卡名（如 `游荡者`、`鬣狗王`），全称由 UI 统一 `${region.name} · ${level.name}` 派生；
  - 方案 B：在展示格式化层增加 `level.name.startsWith(region.name)` 自动消除重复前缀的防御。

---

### 4. 召唤物槽位分配采用贪婪查找，未与先机/阵型规则深度绑定

- **现状**：
  - 当战斗事件派发 `summon`（召唤）时，`BattleModal` 在 6 个槽位中简单使用 `findIndex(s => s === null)` 寻找第一个空槽填入召唤物。
- **妥协点**：
  - 如果玩家只上阵了 1 号位和 6 号位英雄，召唤物会被直接塞进 2 号位，在视觉上可能与玩家预期的阵型站位或召唤师先机位置不符。
- **待完善**：
  - 建立召唤物槽位推荐策略（如优先填补召唤者同排空位/后排空位），并在 `summon` 事件中由引擎附带推荐的 `targetSlotIndex`。

---

### 5. 战斗表现层缺少 MP 消耗动效与暴击/特写视觉分级

- **现状**：
  - `BattleModal` 卡片中展示了静态 MP 条，且事件流中能播报技能消耗与冷却；
  - 暴击（`isCrit`）仅在伤害数字末尾追加了 `!`（如 `-45!`）。
- **妥协点**：
  - 没有技能施放时 MP 消耗清空的平滑动画，也没有暴击时的镜头震颤（Screen Shake）、高亮闪光或特写效果，大招与普通攻击在视觉冲击力上区分度有限。
- **待完善**：
  - 为释放大招（`awaken_nova` 等非 `basic_attack` 技能）增加卡片金色外发光或聚气特效；
  - 暴击伤害飘字采用醒目的亮黄色及放大弹出缩放曲线。

---

### 6. 部分战斗衍生道具在 `GameIcon` 中走 Lucide 降级

- **现状**：
  - 战斗掉落的 `soul_echo`（灵魂残响）、`resonance_shard`（共鸣碎片）以及部分装备图纸，在未配置 Sprite 图集切片时，降级显示为 Lucide 图标（`Gem`、`Sparkles`），并在控制台打印待补提示。
- **妥协点**：
  - 保证了界面绝对不崩溃、不白屏，但视觉质感未能达到全量手绘/像素图集的统一水平。
- **待完善**：
  - 美术资源齐备后，在 `src/data/items.ts` 与 Sprite 映射表中补齐所有战斗货币与掉落物的专用 Sprite 切片。

---

### 7. 区域选择器尚未在远征模块（Expedition）完全收口

- **现状**：
  - `RegionSelectorModal` 已经支持了 `combat` 与 `exploration` 模式，并作为公共组件供荒野 Tab 消费；
  - 但远征系统（`ExpeditionModal`）部分目前仍保留原有的独立卡片列表形式。
- **妥协点**：
  - 原规范（`docs/combat/UI.md`）要求“该组件应能在荒野探索、战斗、远征中都可复用”，目前远征入口尚未彻底对接统一选择器。
- **待完善**：
  - 对远征模块进行接入重构，复用 `RegionSelectorModal(mode="expedition")`，实现全游戏所有玩法区域选择器的 100% 统一。
