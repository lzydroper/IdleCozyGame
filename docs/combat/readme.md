# 概述

战斗系统被拆分为多个部分来实现，具体可见其他 readme 文档。

目标是将战斗系统重构为**拓展性强、可配置性强**的系统：**内容与数值全部配置化，核心引擎只保留固定的规则逻辑**（回合流程、时机派发、伤害公式等），消灭业务逻辑与数值的硬编码，使其成为游戏重要的组成部分。

在重构的同时需要简化代码：将原本散落在各处的硬编码计算统一改为**能力(Ability)、Modifier 与效果(Effect)** 的形式。

> 现状 → 目标 映射（重构边界）：
>
> | 现状模块 | 目标 | 处理方式 |
> |---|---|---|
> | `src/state/statSystem.ts` 的 `StatModifier` | 统一为一种 `Modifier`（见 Effect.md） | 保留属性计算管道，值类型收敛 |
> | `src/state/buffSystem.ts` 的 `ActiveBuff` | 新 Buff 模型（见 Buff.md） | 重写 |
> | `src/state/combatEngine.ts` 的 `calculateDamage` | 伤害结算并入效果管道 | 合并进新引擎，删除与 `combat.ts` 重复的公式 |
> | `src/state/combat.ts` 的 `simulateBattle` 与结算/离线挂机 | Turn + Ability + Level + Offline 的落地 | 重写 |
> | `src/data/combatZones.ts` 区域链 + BOSS | 区域 + 关卡（见 Level.md） | 重写为有序关卡数组 |
> | `src/data/statConfig.ts` | 属性/数值配置 | 保留并扩展 |

按依赖顺序，拆分为以下几个部分，详情见各文件，此处只做总纲：

1. **Turn**（`Turn.md`）—— 回合概念与时机系统，为 buff/effect/ability 做铺垫。
2. **Effect**（`Effect.md`）—— 具体执行效果的最小单位，持有实例辨识字段、来源、目标、效果等字段。
3. **Buff**（`Buff.md`）—— 持有持续时间 Duration、刷新策略 Renew、堆叠策略 Stack、具体效果 Effect 等字段。
4. **Ability**（`Ability.md`）—— 具体拥有行为或能力的单位，包括攻击行为、技能行为等。
5. **Entity**（`Entity.md`）—— 参战实体单位概念上的父类，向下派生英雄、敌人；敌人不分父子类，boss / nightmare 均为敌人的特殊实例（配置标记）。
6. **Level**（`Level.md`）—— 区域与关卡模型，一个区域包含多个关卡，末位关卡通关才算区域通关。
7. **UI**（`UI.md`）—— 战斗界面 UI 的修改调整期望方向。
8. **Offline**（`Offline.md`）—— 挂机战斗功能的修改调整期望方向。

> 以上顺序是**依赖顺序**，除回合功能外，实现顺序不固定，可根据实际需求调整。

## 已敲定的关键决策

- **战斗区域解锁** = 上一区域已解锁 **且** 该区域探索程度达到 100% **且** 满足可选特殊需求。
- **关卡通关记录**：仅使用关卡 id 的 list（数组），不使用 bitmask（避免中途插入关卡破坏记录）。
- **关卡是有序数组**，末位即区域关底；配置上所有关卡同构、同级，不区分 BOSS 关卡，BOSS 只是关卡内的一种敌人特殊实例。
- **退出按钮**：仅独立的战斗页面提供"退出"，退出按战斗失败结算；其余系统（探索等）**只读战斗结果**，不在战斗页面内提供退出；探索的撤离是探索侧操作，无损。
- **离线挂机语义**：在线时持续播放、离线时暂停（详见 Offline.md）。该语义**反转 ADR-0002 的"确认式离线推进"**，需另立 ADR 记录。
- **存档与测试迁移**：本游戏尚未发布、无真实旧存档，**不向后兼容旧存档**；旧测试若与新功能不符一律删除，防止干扰新功能测试。

## 最终预期的战斗体验

玩家进入**战斗**界面（从"挂机战斗"更名为"战斗"）。

- 玩家因为之前已经在挂机战斗了，只能看到挂机战斗相关功能。
- 玩家停止挂机战斗，出现结算提示，出现主动战斗相关功能（两者的切换方式待商榷，可能单独分离 tab，可能整合为"战斗"tab，但一定集成在探索 tab）。
- 玩家选择主动战斗相关功能，可以选择区域，并显示关卡；点击关卡按钮显示弹出信息、敌人详情，按钮选择战斗或取消。
- 玩家选择战斗，进入独立的、新的战斗场景页面。该页面所有战斗场景通用，仅需输入或引用所有参战单位的信息即可进入；页面仅显示双方所有单位的情况与战斗信息；战斗结束后跳转。玩家也可以点击角落的退出按钮，以战斗失败的结局结束战斗。
- 战斗信息会显示：某个时机开始、某个单位触发某个能力、某个来自某单位的效果触发、某个单位受到某个效果的影响、某个单位阵亡或被召唤等信息。
- 玩家从战斗结束中归来，看到结算提示。
- 玩家可以点击进入最后一个已解锁区域的下一个待解锁区域，其中所有关卡信息都处于封锁状态，可以点击查看信息，但进入按钮不可交互。
- 玩家能直观看到待解锁区域的解锁条件。
- 玩家选择挂机战斗，出现简略（可能只显示三条）的战斗信息区域。当玩家在线时，无论玩家是否停留在该界面，战斗过程都会持续进行，体验和主动战斗相近（指播放速度等）；挂机战斗会持续循环玩家当前选择的关卡，每次开始一次新的关卡挂机战斗流程扣除一次体力，每次结束战斗结算收益。每次战斗流程不是恢复状态，而是创建新的战斗快照，所有状态自动恢复，无需额外处理。
- 玩家离线时挂机战斗停止计算，相关信息仅本地保存，云端不保存；玩家重新上线时继续流程。
- 体力的自动回复只与在线时的具体时间流动和离线后的离线时长有关，由其内部维护；外部只能获取当前体力值、请求修改当前体力值（返回是否成功），与其他系统解耦。
