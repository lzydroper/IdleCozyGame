# 概述

战斗系统被拆分为多个部分来实现，具体可见其他readme文档；

目标是将战斗系统重构为拓展性强，可配置性强的系统，杜绝所有的硬编码，是游戏重要的组成部分；

在更新的同时需要简化代码，将原本属性的硬编码计算改为能力或是Modifier或是别的更合理的形式；

按预期的实现顺序，拆分为以下几个部分，详情见文件内叙述，此处只做总纲：

1. Turn，回合，对应文件`Turn.md`。优先实现战斗的回合概念，为后续的buff、effect、ability做铺垫。
3. Effect，对应`Effect.md`。具体的执行效果的单位，持有实例辨识字段，来源，目标，效果等字段。
2. Buff，对应`Buff.md`。持有持续时间Duration，刷新策略Renew，堆叠策略Stack，具体效果Effect等字段。
4. Ability，对应`Ability.md`。具体拥有行为或是能力的单位，包括攻击行为，技能行为等等。
5. Entity，对应`Entity.md`。参战实体单位概念上的父类，向下派生英雄、敌人，其中敌人向下派生boss（也可能派生梦魇，也可能完全不派生，直接就是敌人的特殊实例）。
6. Level，对应`Level.md`。对区域进行改版细化，使得一个区域包含多个关卡，一个区域的最后一个关卡通关才算区域通关，区域通关可能获得特殊奖励，配置上所有关卡统一、同级，一个区域的任何一个关卡都可能有boss单位，一个区域的解锁除了要求上一个区域解锁外，可能还有一些特殊需求。
7. UI，对应`UI.md`。对战斗界面UI的修改调整期望方向。
8. Offline，对应`Offline.md`。对挂机战斗功能的修改调整期望方向。

理论上以上顺序除了回合功能外，实现顺序不固定，可根据实际需求调整；

最终预期的战斗体验如下：

```markdown
玩家进入*战斗*界面（从“挂机战斗”更名为“战斗”）
玩家因为之前已经在挂机战斗了，只能看到挂机战斗相关功能
玩家停止挂机战斗，出现结算提示，出现主动战斗相关功能（这俩者的切换待商榷，可能单独分离tab，可能整合为“战斗”tab，但一定集成在探索tab）
玩家选择主动战斗相关功能，可以选择区域，并显示关卡，点击关卡方形按钮显示弹出信息，敌人详情，按钮选择战斗或取消
玩家选择战斗，进入独立的、新的战斗场景页面，该页面所有战斗场景通用，仅需输入或引用所有参战单位的信息即可进入，该页面仅显示战斗双方所有单位的情况，和战斗信息，战斗结束后跳转，玩家也可以点击角落的退出按钮，以战斗失败的结局结束战斗
战斗信息会显示某个时机开始、某个单位触发某个能力、某个来自某个单位的效果触发、某个单位受到某个效果的影响、某个单位阵亡或被召唤等等信息
玩家从战斗结束中归来，看到结算提示
玩家可以点击进入最后一个已解锁区域的下一个待解锁区域，其中所有关卡信息都处于封锁状态，可以点击查看信息，但进入按钮变为不可交互
玩家能直观看到待解锁区域的解锁条件
玩家选择挂机战斗，出现简略（可能只显示三条）的战斗信息区域，当玩家在线时，无论玩家是否停留在该界面，战斗过程都会持续进行，体验和主动战斗相近（指播放速度等等），挂机战斗会持续循环玩家当前选择的关卡，每次开始一次新的关卡挂机战斗流程扣除一次体力，每次结束战斗结算收益，每次战斗流程不是恢复状态，而是创建新的战斗快照，所有状态自动恢复无需额外处理
玩家离线时挂机战斗停止计算，相关信息仅本地保存，云端不保存，玩家重新上线时继续流程
体力的自动回复只和在线时具体时间流动和离线后离线时长有关，由其内部维护，外部只能获取当前体力值、请求修改当前体力值（返回是否成功），与其他系统解耦
```
