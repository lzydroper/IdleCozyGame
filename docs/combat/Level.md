# 概述

关卡是对战斗区域的进一步细化。当前区域被抽离成三个概念：探索区域、挂机战斗区域、挂机探索区域；本次将它们整合为统一的**区域(Region)**，区域下包含多个**关卡(Level)**。

1. 修改探索现状：当前每次进入只是在事件列表中随机找一个 Event 触发；改为引入区域概念进行分组，玩家在探索前选择要探索的区域，由区域决定初始消耗（替换现有硬编码消耗）。
2. 怪物配置统合进区域内，使探索与战斗的敌人列表统一。
3. 探索是最先解锁区域的地方：只有对某区域的探索程度达到某数值，才能在探索中解锁其他区域。
4. 同时为后续全json化做兼容

## 解锁模型

- **战斗区域解锁** = 上一区域已解锁 **且** 该区域探索程度达到 100% **且** 满足可选特殊需求。
- **关卡解锁** = 仅与该区域内上一个关卡是否解锁有关（线性）。
- 战斗事件冗余清理：扣除体力不是战斗事件负责，而是由触发战斗事件的事件申请、体力系统审核。

## 关卡

- 区域内包含多个关卡，**关卡是有序数组，末位即区域关底**；通关末位关卡 = 区域通关。
- 底层实现不区分 BOSS 关卡；配置上所有关卡同构、同级，仅可在某个关卡配置里放入 BOSS 敌人（BOSS = 敌人的特殊实例，见 Entity.md）。
- **通关记录仅使用关卡 id 的 list（数组）**，不使用 bitmask（避免中途插入关卡破坏旧记录）。

## 掉落与奖励

- 关卡负责记录战利品列表，并额外维护首次通关的特殊战利品（可空）。
- 经验等掉落不归怪物维护，而由关卡维护；胜利获得全部，失败没有。
- 掉落统一为物品，只记录 id 与数量/概率，不单独维护经验、灵魂残响等特殊物品。三种形态：
  - 固定：`{ id, cnt }` —— 必定掉落 `cnt` 个；
  - 概率：`{ id, cnt, chance }` —— `chance` 为整数百分比，`25` 表示 25% 掉落率（配置更直观）；
  - 权重轮盘：`[{ id, cnt, weight }, ...]` —— 池子中多种物品根据 `weight`（纯权重整型）仅选出一个，必定掉落其中一件；UI 显示概率由 `weight / totalWeight × 100` 计算后格式化为百分比。

> 约定变更：现有 `CombatDropConfig.chance` 为 0–1 小数（如 `1.0`、`0.5`）。本次统一为**整数百分比**（`100`、`50`），落地时需同步迁移 `src/data/combatZones.ts` 与探索事件中的既有掉落表。
