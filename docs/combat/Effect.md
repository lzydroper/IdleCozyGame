# 概述

Effect 是具体行为的最小执行单位，不保存具体时机，被触发时立即执行动作；可由 Buff 或 Ability 创建，可注册到特定时机被调用，也可在创建时立即执行。

- 效果需要保存**来源(source)**和**目标(target)**；效果不负责计算，只是某次操作的记录，创建时应传入需要的数值。
- 效果可理解为**指令/命令(command)**：所有技能、Buff、攻击导致的行为都由效果执行，保证基础效果种类足够，使所有体系直接复用效果逻辑，而非各自另写逻辑。
- 目标可以是任意单位，用于记录生效的单位；来源是因为部分特殊技能需要读取来源执行操作（如反伤：受到伤害时读取来源，生成反击伤害效果给予来源——不复用伤害效果或加特殊标记，防止无止境递归），确保单位之间完全解耦。

## 创建与审核链路

`Ability → Effect（apply buff effect）→ Buff → Effect`，或 `Ability → Effect`。

Ability 与 Buff 都只负责**派发 Effect**；对效果的审核（如判断目标抵抗是否高于来源抵抗、该效果是否被无效化、是否执行）在效果落地阶段统一处理，Ability 与 Buff 无需各自判断。

## 统一 Modifier

无论是"属性加成"还是"修正某次效果数值"，本质都是**对某个特定数值做加算或乘算修改**，因此统一为一种 `Modifier`，避免 `StatModifier` / `EffectModifier` 两个近似类型造成歧义：

```
Modifier {
  target: 'stat.<StatKey>' | 'effect.<参数名>',  // 命名空间区分作用对象
  op: 'add' | 'multiply',                         // add=加算(flat), multiply=乘算(percent)
  value: number,
  source?: string
}
```

- `target` 为 `stat.*` 时：作用于属性面板，由属性计算聚合（多来源 percent 加算后统一乘算）。
- `target` 为 `effect.*` 时：作用于某一次效果的参数，在该效果作用前一次性修正（如"受到治疗 +10%"即 `target: 'effect.heal'`）。

形状统一，语义靠 `target` 命名空间区分。

## 效果的三阶段与回调

效果需要三个阶段：

1. **作用前**：告知效果将要作用，谁要拦截或修正（在此应用 `effect.*` 类 Modifier）。
2. **作用中**：落地目标实际效果，目标收到数值后自行计算实际影响。
3. **作用后**：告知效果已经作用，谁要触发回调。

效果需要有**完成回调**，例如"造成的伤害击杀时恢复 20 点 MP"这个 Buff：由伤害效果触发回调，该 Buff 接收信息判断目标是否死亡，死亡则创建回复 MP 的效果。

## 效果举例

- 伤害：造成 {5} 点 {属性} 伤害
- 伤害：造成 {10}% 最大生命值伤害
- 减益：减少 {5} 点 {体质} 属性值
- 增益：增加 {5} 点 {力量} 属性值
- 治疗：回复 {20} 点生命
- 眩晕：跳过本回合
- 驱散：去除 {眩晕} Buff
- 免疫：免疫 {火} 属性伤害
- 免疫：免疫 {虚弱} Buff
- 嘲讽：提高 {5} 点被攻击优先级
- 召唤：召唤 {2} 个 {骷髅} 单位
