# 概述

effect效果是一个具体行为的基本单位，不保存具体时机，被触发时立即执行动作，可由buff或ability创建，可被注册到特定时机被调用，也可以在创建时立即执行，是抽象出来的最小动作单位。

效果需要保存来源和目标，效果不负责计算，只是某次操作的记录，创建时应传入需要的数值。

效果也可以理解为标签，所有的技能、buff、攻击导致的行为都需要由效果来执行，保证基础的效果种类足够使得所有体系能够直接调用效果的逻辑而非另外自己编写逻辑。

其中目标可以是任何单位，用于记录生效的单位，而来源是因为部分特殊技能可能需要读取来源来执行某些操作，如反伤技能，在受到伤害效果时触发，读取来源，生成造成反击性质的伤害的效果给予接受到的来源（不复用伤害效果或特殊标记防止无止境递归），确保单位之间完全解耦，不需要复杂的引用。

效果可以理解为标签，只需要传入固定数值和来源和目标来创建，注册时机由创建者来申请。

具体的创建链路可能为ability->effect（apply buff effect）->buff->effect，也可能为ability->effect，即ability和buff都只负责派发effect，对effect的审核，如判断目标的抵抗是否大于来源的抵抗以决定该effect是否被无效化，是否执行，ability和buff无需判断。

效果需要有完成的回调，比如“造成的伤害击杀时恢复20点mp”这个buff，需要由伤害效果触发回调，该buff接收信息查看目标是否死亡，死亡则创建回复mp的效果。

效果的数值应该也能被Modifier，如某个buff会监听当受到治疗效果时，使得治疗效果提升，此时需要令该治疗效果添加Modifier后再生效；总之效果需要有作用前（告知效果将要作用，谁要拦截或是修正），作用中（落地目标实际效果，目标收到数值后自己计算实际影响），作用后（告知效果已经作用，谁要触发这个回调）三个阶段。

效果的举例如下：
伤害：造成{5}点{属性}的伤害
伤害：造成{10}百分比的最大生命值伤害
减益：减少{5}点{体质}属性值
增益：增加{5}点{力量}属性值
治疗：回复{20}点生命
眩晕：跳过本回合
驱散：去除{眩晕}buff
免疫：免疫{火}属性伤害
免疫：免疫{虚弱}buff
嘲讽：提高{5}点被攻击优先级
召唤：召唤{2}个{骷髅}单位
