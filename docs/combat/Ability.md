# 概述

能力是更高一层的抽象，所有的主动行为都应该归结为能力，所有的持久性被动也应归结为能力，总之能力是最高层的容器，用于派发Buff和Effect。

具体可以算作能力的有攻击行为，天赋被动（比如某个天赋解锁后获得被动吸血，每次普通攻击恢复造成伤害的一定百分比hp），技能等等。

能力需要承担计算的职责，能力不直接生效，具体效果应由Effect承担，能力用于配置层、展示层，用于派发Buff和Effect；

能力的作用流程为先根据来源的相关数值和传入的一些数值（比如某个技能的数值公式涉及到了单位的技能等级，力量属性等），计算出来源测的最终数值，然后生成Buff或Effect，具体实际造成数值则是目标接收到Effect后自行计算

理想的作用流程为：

1. Ability计算数值和收集入参（如算出伤害为a，暴击率为b，暴击倍率为c）
2. 组装并分发 Effect
3. Effect结算，目标解析并计算实际伤害（如抗暴击率为d，防御为e，加上读入的参数，最后根据公式一次算清）

其中数值的拦截与修正（如"受到治疗提升"）一律走统一 Modifier（见 Effect.md），Ability 不自行判断、不自行改数。

Ability作为类似技能的承载体，应至少实现消耗（不硬编码限定具体资源）、冷却（回合数）、可计算触发优先级等，同时也需要为后续的全json化数据配置做铺垫
