# 概述

战斗分为多个轮次，轮次中所有时机名词为：

> **轮次开始前**：每个轮次正式进入前，用于预计算回合进行次序、技能时机等
>
> **回合开始前**：每个回合正式进入前，用于技能时机、判断是否为死亡状态跳过至下一名角色等
>
> **回合进行中**：每个回合正式执行中，用于技能时机、攻击行为等
>
> **回合结束后**：每个回合完全结束后，用于技能时机等
>
> **轮次结束后**：每个轮次完全结束后，用于技能时机

每个轮次所有参与战斗的未死亡单位都拥有一个回合，回合次序由**`先机`**属性来决定，该值越大越先行动；

先机属性值会在正式进入战斗前计算，并内部维护一个优先队列，来决定下个回合由谁行动；

先机属性不对玩家自己暴露，玩家无法直接知道具体值，但开发者应有渠道知道；

先机属性在战斗前计算一次初始值，公式为：$100 + \frac{agility}{agility + 100}*100 + clamp(fixval, 0,100)$，其中agility为元属性，fixval为特殊单位拥有的修正值，特殊单位指召唤物、boss等，英雄绝对没有fixval或该值初始一定为0，先机属性上限为300；

先机属性在战斗时可能因为技能或buff效果产生变动，其变动只会以固定int值加算或减算改变fixval，战斗中对agility的影响不会改变先机属性值；

轮次中所有时机的预期维护的实现形式为，每个时机拥有一个注册机制，以及对应效果映射列表，单位需要依靠时机发动的效果需要向总的轮次管理系统申请：哪个时机，效果实例辨识字段，来源，目标，具体效果内容。每个时机进行时会按注册顺序（可能需要逆序）结算效果，某个效果的结算可能产生：在另一个时机注册某个效果，在当前时机注销某个效果等。

战斗中可能因为召唤物，先机属性变动导致回合结算次序的变化。

一个战斗场景的预期流程为：

1. 计算所有参战单位的属性快照
2. 计算所有参战单位的先机属性初始值，并开始维护待参战优先队列和已参战优先队列
3. 结算所有轮次开始前的效果
4. 从待参战优先队列中取出先机属性最大值的单位，若该单位已阵亡或因为特殊效果回合无法行动，则直接进入回合结束阶段；否则依次结算该单位的回合开始前、回合进行中、回合结束后效果，然后将其加入已参战优先队列
5. 反复执行4直到待参战队列为空，交换两个队列的定义或别的更好的实现方式，结算所有轮次结束后的效果
6. 反复执行3-5直到某一方所有单位阵亡，或特殊效果使得战斗结束，结束战斗
