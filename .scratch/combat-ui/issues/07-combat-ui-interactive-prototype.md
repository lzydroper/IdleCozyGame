# 07 — 战斗 UI 高保真交互原型（Interactive Prototype）

Type: prototype
Status: resolved
Blocked by: 02, 03, 04, 06

## Question

如何通过可交互的 HTML 原型验证战斗 UI 的视觉体验、动效节奏与弹窗交互流？需决议与验证：

1. **原型结构 (位于 `docs/prototypes/combat-ui/`)**：
   - `prototype.html` / `prototype.js` 单独完整可用；
   - 包含主导航切换：`探索 -> [荒野 | 战斗]`；
   - 区域选择器组件：两级弹窗（列表 -> 详情，展示已解锁与未解锁锁住原因诊断）；
   - 关卡列表与关卡详情弹窗（展示敌人配置、体力对比、掉落预览、迎战/挂机按钮）；
   - 独立全屏战斗场景模态（包含 3v3 卡片血条、MP、Buff、飘字动效、事件流滚动、退出按钮二次确认、跳过结算）；
   - 挂机战斗看板（包含实时体力条、3 行精简战斗轮播、停止挂机结算）。
2. **用户交互验证点**：
   - 验证三段式战场排版在移动端/窄屏下的紧凑度与可读性；
   - 验证事件流播放节奏（1x / 2x）与血条扣减、漂字视觉效果；
   - 验证区域未解锁原因的诊断展示是否直观清晰。

产出：`docs/prototypes/combat-ui/` 独立原型代码与用户确认。

## Answer

（Prototype 验证完成）

- **产出原型**：[docs/prototypes/combat-ui/prototype.html](file:///e:/%E7%B3%BB%E7%BB%9F/%E6%96%87%E6%A1%A3/GitHub/IdleCozyGame/docs/prototypes/combat-ui/prototype.html) 与 [prototype.js](file:///e:/%E7%B3%BB%E7%BB%9F/%E6%96%87%E6%A1%A3/GitHub/IdleCozyGame/docs/prototypes/combat-ui/prototype.js)。
- **核心验证与设计规范**：
  1. **弹窗与容器尺寸规范统一**：全项目弹窗、卡片容器与操作按钮高度严格统一（弹窗 `rounded-3xl`，操作按钮高度统一为 `h-9.5`，控制栏小按钮统一为 `h-8`，操作按钮一律固定为【确认】与【取消】，不可交互时仅置灰禁用，杜绝文案跳变）；
  2. **主导航与子 Tab**：「探索」主 Tab 下「荒野 / 战斗」双字子 Tab 切换，荒野与战斗区域更换均采用全卡片可点击交互；
  3. **区域选择器诊断与单步揭示**：仅展示所有已解锁区域 + 最近 1 个待解锁区域（后续深层锁定区隐藏）；支持进入待解锁区域查看关卡，全关卡封锁、详情只读、确认按钮置灰不可交互；
  4. **关卡小方块网格**：关卡采用类似物品格的小方块网格呈现；挑战与挂机模式均展示全关卡，挂机模式下未通关关卡统一标示「未解锁」，详情弹窗内提示锁住原因；
  5. **全屏独立战斗场景（`BattleView`）**：
     - **顶部**：卡片容器封装关卡名、轮次、调速（1x/2x）、单次跳过、退出（主动战提供退出确认判负，遭遇战隐藏）；
     - **中部固定 6v6 战术板（Zero Layout Shift）**：左右各 6 个纯竖向全宽固定卡槽（总高固定 `310px`），无多余表头标题；标签后置（如 `魔导构造体 [召唤物]`、`剧毒蜂后 [首领]`，无杂兵标签）；单位阵亡原地保留并显示 `0/maxHp [阵亡]`，召唤物入驻固定空槽，彻底杜绝高度跳变；
     - **下部战况事件流**：`flex-1` 弹性填满剩余空间，无多余标题栏，文字排版清晰舒适平滑滚动；
  6. **挂机监控看板（`IdleCombatWidget`）**：沉浸展示，固定 3 行高度完整事件流窗口平滑推进，开战即扣体力、停止不退体力，停止挂机集中汇总战利品。
