# 01 — 导航与 Tab 层级架构（「探索」主 Tab 与「荒野/战斗」子 Tab）

Type: grilling
Status: resolved
Blocked by: (无)

## Question

如何统一地表探索与战斗的入口层级及双字命名规范？需决议：

1. **入口组织**：底部一级导航保持「探索」（原荒野/探索入口），内部二级子 Tab 统一命名为双字：`荒野` 与 `战斗`。
2. **子页面职责划分**：
   - 「荒野」子 Tab：负责地表手动随机事件卡牌探索（SwipeCard / 事件结算 / 临时背包 / 救援任务触发）。
   - 「战斗」子 Tab：负责区域与关卡浏览、主动挑战、挂机循环开启与挂机看板监控。
3. **状态切换与联动**：
   - 处于手动探索中（`inRealityExploration: true`）时，自动聚焦「荒野」子 Tab；
   - 处于挂机战斗中时，「战斗」子 Tab 展示实时挂机看板，不阻塞玩家切换到「荒野」进行手动探索（或是否允许同时挂机与手动探索）。
4. **全 JSON 数据化兼容**：Tab 定义与模式映射提取为静态枚举/配置，无硬编码与闭包依赖。

产出：Tab 导航容器组件结构、命名规范与多状态流转契约。

## Answer

（HITL grilling，根据用户反馈精简收敛）

- **D1 导航命名与图标**：底部主 Tab 保持「探索」（图标 `Compass`）；内部二级子 Tab 统一改为双字名称，保留原图标：
  - `荒野`（图标 `<Map />`，原荒野探索）；
  - `战斗`（图标 `<Swords />`，原挂机战斗）。
- **D2 探索中界面自然呈现**：进入手动荒野探索时（`inRealityExploration: true`），界面自然全量展示探索卡片与临时背包，无需额外复杂的锁定逻辑。
- **D3 挂机与探索边界**：挂机循环的并发推进属于 `Offline.md` 范畴；UI 仅根据 `state.combat.idle` 是否存在只读呈现「战斗」子 Tab 下的挂机看板或关卡列表。
- **D4 保持 UI 简洁适度**：子 Tab 为固定 UI 视图，直接以标准 React 状态（`mode: 'explore' | 'combat'`）与 JSX 组织，不作过度配置抽象；JSON 数据化重点放在区域/关卡/掉落等游戏内容数据层。
