# 03 — 关卡浏览与关卡详情交互（LevelBrowser & LevelDetailModal）

Type: grilling
Status: resolved
Blocked by: 02

## Question

在「战斗」子页面选定区域后，关卡列表与关卡详情弹窗如何组织与交互？需决议：

1. **关卡列表呈现流 (LevelBrowser)**：
   - 线性关卡节点列表（有序数组，末位为关底/BOSS 关）；
   - 关卡状态可视化：`已通关`（绿色勾选 / 首通标记已领）、`可挑战`（当前解锁关卡）、`锁定`（置灰 / 显示需通关上一关）；
   - 关卡卡片精简信息：关卡编号、关卡名称、体力消耗、BOSS 图标标记。
2. **关卡详情弹窗 (LevelDetailModal)**：
   - 点击关卡卡片后弹出模态窗口；
   - 信息呈现：
     - 敌人阵容一览（敌人立绘/图标、名称、角色标签 normal/boss、属性概览）；
     - 体力消耗对比（当前玩家体力 vs 消耗体力）；
     - 战利品展示（首通特殊奖励 + 常规掉落池与百分比概率）；
   - 操作按钮：
     - 【迎战 / 主动挑战】：体力足够且队伍就绪时可用，点击进入独立全屏战斗场景；
     - 【挂机战斗】：仅在已通关关卡上可用（未通关置灰并提示），点击开启在线挂机循环；
     - 【取消 / 关闭】。
3. **全 JSON 兼容**：掉落池展示与概率格式化完全数据驱动。

产出：关卡列表容器与 `LevelDetailModal` 规格说明。

## Answer

（HITL grilling，根据用户反馈精简卡片与统合弹窗交互）

- **D1 关卡小卡片精简呈现与统一状态标记**：
  - 关卡小卡片仅显示「序号与名称」（如 `01 荒野哨所`），不显示体力标签；
  - 状态标记统一归敛为三类：`已通关`、`可挑战`、`未解锁`（已解锁区域中未解锁的关卡、以及未解锁区域下的所有关卡，均统一标记为 `未解锁`）。
- **D2 关卡详情弹窗（LevelDetailModal）信息与双按钮规范**：
  - 仅展示关卡标题、敌人阵容一览（含 BOSS 标记）、关卡所需体力消耗（不重复展示当前体力，顶部已有全局体力栏）、战利品情报（首通奖励 + 常规掉落池）；
  - 操作按钮固定为两个：【确认】与【取消】。
- **D3 主动战斗 vs 挂机模式复用与语义分流**：
  - **主动战斗模式**：展示全量关卡（含通关/挑战/未解锁状态），点击关卡后弹窗确认按钮语义为【确认战斗】（进入全屏独立战斗场景）；
  - **挂机模式**：仅列出当前选定区域的所有**已通关关卡**（无状态标记），点击关卡后复用详情弹窗，确认按钮语义变为【确认挂机】（开启在线挂机循环并切入挂机看板）。
