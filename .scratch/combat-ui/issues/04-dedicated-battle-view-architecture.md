# 04 — 独立全屏战斗场景页面架构与复用（Dedicated BattleView）

Type: grilling
Status: resolved
Blocked by: 01

## Question

独立的、统一的、可复用的全屏战斗场景页面如何构建与多场景对接？需决议：

1. **模态形态与全屏架构**：
   - 顶层全屏浮层模态（对齐 `SummonTab` / `isBattleOpen` 模式），屏蔽底层主导航；
   - 纯战斗信息呈现，去除温室/工坊等外部系统干扰。
2. **三段式战场布局**：
   - **顶部仪表盘**：区域/关卡名称、轮次进度指示（`Round 3/30`）、调速器（1x / 2x）、跳过战斗按钮、退出按钮（右上角，条件渲染）；
   - **中部（对战阵列）**：左侧我方 3 名英雄卡片，右侧敌方 1~3 名敌人卡片；每个单位实时显示：头像/立绘、名称、HP 动态血条（当前/最大值）、MP 条、Buff/Debuff 图标与层数、行动状态指示；
   - **下部（战况事件播报区）**：事件流逐条平滑滚动播放（能力施放、伤害/治疗、状态附加、阵亡等），支持伤害数字漂字与受击高亮动效。
3. **战斗结束与结算流**：
   - 战斗播放完毕后唤起结算浮层（展示胜利/失败/平局、战利品明细、经验收益、重伤英雄提醒）；
   - 点击【确认返回】后关闭全屏战斗场景，无缝回到调用方上下文。
4. **全 JSON 兼容**：战斗播报文本模板与动画配置纯数据驱动。

产出：`BattleView` / `BattleModal` 组件接口与状态机设计。

## Answer

（HITL grilling，确认纯前端 UI 容器与全屏场景架构）

- **D1 顶层全屏模态形态**：对齐 `SummonTab` 设计模式，作为 App 顶层浮层（`fixed inset-0 z-50`）；进入战斗后仅展示战斗信息，屏蔽底层主导航及外部系统干扰。
- **D2 复用既有数据快照**：底层计算与快照引擎已就绪（`CombatSettlement` / `BattleResult`），UI 层仅作为纯展现容器消费入参快照与结算包，不耦合战斗逻辑计算。
- **D3 三段式战场布局骨架**：
  - 顶部：关卡标题、轮次计数、1x/2x 调速与跳过按钮、条件渲染的退出按钮；
  - 中部：左侧我方英雄阵容 vs 右侧敌方阵容，展示头像、名称、HP 动态血条、MP 条、Buff 图标列表；
  - 下部：战况事件日志平滑滚动展示；
  - 结算浮层：战斗播放结束或跳过时弹出结算结果，点击确认退出场景。
- **D4 细节动效验证前置**：具体的血条平滑步进、伤害漂字、受击反馈等视觉动效细节，在 07 号原型中完整调校验证。
