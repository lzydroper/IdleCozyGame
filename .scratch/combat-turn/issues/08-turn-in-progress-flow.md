# 08 — 回合进行中子流程（决策）

**Type:** grilling
**Status:** resolved
**Blocked by:** None

## Question

「回合进行中」是否固化为标准子流程：**选能力 → 选目标 → 派发效果 → 派发细粒度事件**？

需决议：

1. 该子流程是否作为 Ability 的调用契约（Turn 只驱动骨架，Ability 填充「能力」与「效果」）？
2. **普通攻击**是默认能力（作为每个单位的兜底 Ability）还是 Turn 特判？
3. 细粒度事件（攻击后/受到伤害/受到治疗/死亡/召唤）在子流程中的派发时点与顺序？
4. 该子流程与 03（确定性）如何保证派发顺序固定？

产出：回合进行中的标准子流程契约（供 Ability/Effect 接入）。

## Answer

（HITL grilling，用户全部确认推荐方案）

- **D1 子流程归属**：Turn 只驱动骨架——「回合进行中」调用该单位的**行动入口**，选能力/选目标/派发效果归 Ability；Turn 不自选能力、不自选目标。
- **D2 普通攻击**：普通攻击 = **兜底 Ability**（每个单位默认持有、Ability 层提供），非 Turn 特判。
- **D3 细粒度事件时点**：事件**不是独立最后一步**，而在效果结算/行为完成时**即时派发**（全部在「回合进行中」内）：伤害结算时派「受到伤害」、hp 归零时派「死亡」、召唤落地时派「召唤」、攻击完成时派「攻击后」；「回合结束后」是独立主时机，在行为+事件全部结算完后才进。
- **D4 确定性**：Turn 固定骨架顺序（回合开始前→进行中→结束后）+ Ability/Effect 内固定派发顺序（效果 FIFO/注册序、事件随效果序即时派发）+ 种子化 RNG（03）；同输入同种子 → 同事件流。
