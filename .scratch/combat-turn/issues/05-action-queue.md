# 05 — 行动队列实现（决策）

**Type:** grilling
**Status:** resolved
**Blocked by:** None

## Question

行动队列用「双队列交换」还是「单优先队列 + 轮次分隔标记」？

- **A)** 双队列：待参战队列 + 已参战队列，轮末交换两者定义；
- **B)** 单优先队列 + 轮次分隔标记：一个队列按先机排序，用标记分隔「本轮待行动」与「下一轮」区间。

需决议：

1. 选 A 还是 B？（推荐 B，避免双份状态与交换语义）
2. 先机变动（fixval 加减）如何反映到队列（原地重排 vs 重新插入）？
3. 召唤物入场（见 07）如何插入队列？
4. 队列/轮次边界的遍历算法如何保证确定性（配合 03/06）？

产出：行动队列数据结构 + 轮次边界算法（可附状态机/伪代码草图）。

## Answer

（HITL grilling，用户全部确认推荐方案）

- **D1 队列结构**：选 **B** —— **单优先队列 + 轮次分隔标记**（一个队列按先机排序，标记分隔「本轮已行动」与「本轮未行动」），避免双队列的交换语义。
- **D2 先机变动**：选 **A** —— 只重排「本轮未行动」区间的相对顺序；已行动单位锁定在「已行动区」，一轮只行动一次，不回退不插队。
- **D3 中途插入**：单队列结构必须支持**中途插入到「未行动区间」**（召唤物入场即进入未行动区按先机排位）；「排位 vs 插队」具体规则归 **07**。
- **D4 轮次边界算法**：取「未行动区」队首（先机最高）→ 执行其回合 → 移入「已行动区」；「未行动区」空 → 结算「轮次结束后」→ 已行动区整体移回未行动区进入新一轮；每轮检查终止条件（全灭/超限/强制结束标记）。确定性 = 全序排序键（06 定死）+ 固定遍历算法（本票定死）。
