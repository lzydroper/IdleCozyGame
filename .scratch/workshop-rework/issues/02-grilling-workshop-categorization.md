# 工坊分类栏位设计

Type: grilling
Status: resolved
Blocked by:

## Question

工坊的分类栏位按什么维度定义？（用户需求第 2 点：分类定义、方法待讨论）

候选维度：

- **按产出物类别**：对齐背包 `ItemCategory`（道具/资源/碎片/装备），配方按 reward 主产物归类；
- **按配方用途**：生存补给 / 材料加工 / 装备锻造 / 建筑扩展等业务语义；
- **按设施归属**：手动/自动/冶炼炉/组装机（若与 01 调研结论相关）；
- **可配置组合**：分类定义放 `data/`，配方通过字段声明所属分类。

需要决议：

1. 采用哪个（或哪些）维度？推荐方案与理由。
2. 分类如何数据驱动：分类定义（id/标签/图标/排序）放哪个 data 文件？配方如何声明分类（推导 vs 显式字段）？
3. 是否保留"全部"入口（背包系统无"全部"，工坊是否一致）？
4. 空分类的展示策略。

产出：分类栏位的完整设计决议，写入 spec 的分类章节。

## Answer

（2026-08-06 与用户 grilling 决议）

**1. 维度**：按产出物类别对齐背包 `ItemCategory`（道具/资源/碎片/装备），配方分类以 reward 主产物为准；另设补充类 **「建筑」**（收纳无产物的建筑类配方，如温室扩展坞）。充能配方（稳定胶囊充能）归「道具」（产物为道具充能次数）。

**2. 数据驱动**（用户需求第 5 点）：
- 分类定义（id/标签/图标/排序）进 `data/`，可配置可扩展（不写死为 5 类）。
- 配方分类 = **默认从 reward 主产物的 `ITEMS_CONFIG.category` 推导**（单一真相源，与物品类别永不漂移）；无 reward 或需覆盖的配方**显式声明** `category` 字段。
- `Recipe` 增加可选 `category?: ItemCategory | 'building'`（可扩展联合类型），推导规则：reward 主产物（唯一或数量最大者）。

**3. 栏位形态**：固定显示 **5 类**（道具/资源/碎片/装备/建筑），**无「全部」**入口；空分类（含因蓝图锁定隐藏后变空的分类）显示空态（与背包 `LogTab` 空分类逻辑一致，判定基于**可见配方**）；分类列表由 data 配置驱动，后续可扩展。

**4. 分布核对**（27 配方）：道具 12（含充能配方）、资源 7、装备 7、碎片 0（空态）、建筑 1（温室扩展坞）。

→ 分类字段方案已提示 ticket 05（配方数据模型）纳入；「配方展示元数据」（图标/配色/排序）随 04 架构决议与 spec 汇编展开。
