# 03 — 生产 UI 交互原型

Type: prototype

Status: resolved

Blocked by: 01 — production-task-state-machine

## Prototype（资产链接）

原型位置：`docs/prototypes/production-rework/prototype.html`（配套 `prototype.js`，浏览器直接打开即可，无需构建）。

三个结构性差异变体，底部浮动条或 `?variant=A|B|C` 切换（键盘 ← → 也可）：

- **A — 内联一体化（Single-card）**：设备卡内直接展开"配方选择 + 批次滑条 + 消耗/产出预览"，开始后同卡切换为任务进度态。
- **B — 弹窗配置 + 卡片状态（Modal-driven）**：卡片只显示状态摘要，点「生产」弹滑条弹窗（对齐工坊 CraftBatchModal 心智），「取消」弹确认框带退款预览。
- **C — 任务总览列表（Control-center）**：产线页顶部任务总览表（所有设备的进度/已产/目标/取消一行一个），设备卡只留静态信息；新任务在行内展开配置。

## Question

生产交互的 UI 形状是什么？产出廉价原型（stub/静态结构即可，用于讨论"看起来/用起来怎样"），不实现真实逻辑。

需要原型化的部分：

1. **选配方 + 滑条定数量**：参考工坊 `CraftBatchModal` 的滑条交互（上限 = 当前材料可支撑的最大批次数；显示消耗预览/产出预览）。设备待机时如何进入"设定生产"（点设备卡片上的「生产」按钮弹出？还是内联展开？）。
2. **任务卡**：任务进行中的展示——进度条（当前批进度 or 总进度）、"已产 X / 目标 N"、剩余时间、当前批剩余秒。与升级卡（0019 的进度条样式）视觉是否统一？
3. **取消与退款提示**：取消按钮 + 退款预览（"取消将退还：合金金属板 ×63"）——是否弹确认框（参考 `ToastSystem` 的 `showConfirm`）？
4. **多台设备并列**：扩建后多台设备各自独立任务，基建 tab（升级卡）与产线 tab（任务管理）的信息分工——产线 tab 是任务操作主界面（沿用现有 `FacilityCard` 布局改造），基建 tab 只留升级/扩建（已实现）。

- 本票阻塞于 01（任务字段形状决定任务卡展示什么）。

## Resolution

**决议（用户拍板：采用变体 B，弹窗驱动）**：

1. **设备卡 = 状态摘要**（参考原型变体 B）：
   - 待机态：设备名 / 等级 / **驻守按钮**（保留原有 `DutyAssignModal` 指派入口，显示当前驻守英雄与加成摘要：速度/产量/原料减免）/「＋ 生产」按钮。
   - 生产中态：设备名 / 生产中徽章 / 配方名 / 进度条（当前批）+ "已产 X / 目标 N 批" + 当前批剩余 + 总剩余时间 / 每批产出（含驻守加成）/「取消任务」按钮。
2. **「生产」→ 弹窗**（对齐工坊 `CraftBatchModal` 心智）：配方选择 + 批次滑条（上限 = floor(材料 / 每批折扣成本)，按驻守加成折扣后计算）+ 消耗 ×N / 产出 ×N 预览（每批产出按产量加成 floor 后显示）+「开始生产（立即扣除全部材料）」。
3. **「取消」→ 确认弹窗**（`showConfirm`）：显示退款预览——"已产出的 X 批将保留，将退还：材料 ×Y"（Y = (targetCount − completedCount) × 每批折扣成本）。
4. **驻守入口保留**（用户强调）：设备卡上驻守按钮/弹窗原样保留；驻守加成实时作用于任务计算（滑条上限、每批产出、批次耗时）与卡片/弹窗展示。
5. **多台设备**：每台设备一张独立卡（各自的生产弹窗/驻守/取消），扩建后并列展示。
6. **基建 tab 不变**：升级/扩建卡仍在基建 tab（0019 实现），产线 tab 只做任务管理 + 驻守。
