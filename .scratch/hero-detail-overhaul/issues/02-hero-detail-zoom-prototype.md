# 英雄详情弹窗放大优化原型（三列结构保持）

Status: resolved
Type: prototype
Blocked by:

## Question

为英雄详情弹窗（HeroDetailModal）主体制作放大优化原型（用户决策：**保持三列结构**，只做视觉密度放大），供用户在原型上对比选定方案。

背景与约束：

- 现状字号极密：主体大量 `text-[7px]~[9.5px]`（经验值、后勤卡片、属性面板、按钮等），用户感知「元素过小、显示空」。
- 三列骨架不变：左列装备（3 槽 + 一键装备/卸下）、中列（大头像/名称/星级/职阶阵营 + 经验值 + 后勤档案卡片 + 批量升级/升级按钮）、右列技能（3 个占位槽，**保持占位不动**）+ 下半部（天赋树入口 + 6 项基础属性 2×3 网格）。
- 中列元素最多最挤，是放大的主要矛盾区。

原型维度（每变体统一一套「放大规格」）：

1. **字号阶梯**：正文/标签/数值/按钮各档字号（现状 7-9.5px → 建议 9/10/11px 级），与 DetailedStatsModal（text-xs=12px）的观感差距如何弥合。
2. **图标与头像**：装备框/技能框（w-15）、头像（w-22）、按钮图标（w-3.5~6）的放大比例。
3. **间距与密度**：三列间 gap、卡片内 padding、按钮高度、属性网格间距的平衡（放大后不溢出 460px 定高容器）。
4. **长文本处理**：放大后名称/数值/后勤文案的截断与换行策略。

产出：2-3 个放大变体（可切换对比，参考 hero-module-overhaul 的 `?variant=` 原型切换范式），用户选定 1 个 + 明确的放大规格（字号/图标/间距 token 数值），作为「相关子弹窗设计语言统一」ticket 的字号阶梯依据。

## Answer：用户选定变体 C（激进放大，紧凑）（2026-08-07）

三轮反馈迭代：首版布局类冲突导致溢出 → 结构对齐真实骨架 + 垂直预算修复（框保持 w-15 放大框内图标、头像 w-18→w-20、下半部 125→112px、按钮 py-2→py-1）→ 属性项 py-0.5 + gap-2 解决边框拥挤。最终用户反馈「现在的 C 很完美，非常紧凑」。

**选定规格（C，已折入真实 HeroDetailModal，提交 `1806503`）**：
- 字号阶梯：正文/数值/按钮 `text-[11px]` · 标签 `text-[10px]` · 辅助小字 `text-[9px]`（装备名/技能名保持 8.5px、强化角标 7.5px、碎片行 7.5px）
- 图标：装备/技能框内 `w-7 h-7` · 属性项图标 `w-4.5 h-4.5` · 按钮内图标 `w-4`
- 头像：`w-20 h-20`（原 w-18）；按钮统一 `py-1`
- 下半部：`h-[112px]`（原 125）· 属性项 `py-0.5` + `gap-2` + `leading-tight`

**关键设计约束发现**：容器 460px 定高（max-h-68vh），三列内容区约 240px——放大有垂直预算，必须从间距/区块挤出空间。此发现写入原型归档 README，后续 03 号（子弹窗统一）以此为字号阶梯依据。

**原型归档**：`prototype-archive/`（README + 三变体 + 入口 + switcher），HeroTab 原型入口已移除，src 无 throwaway 残留。
