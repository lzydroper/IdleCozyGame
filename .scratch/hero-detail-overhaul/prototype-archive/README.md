# 英雄详情放大优化 UI 原型归档（PROTOTYPE — throwaway primary source）

来源：02 号 ticket 的原型阶段（2026-08-07）。

## 结论

用户**选定变体 C（激进放大，紧凑）**，经历三轮反馈迭代：

1. **首版**：三列骨架类冲突（`flex-1`/`shrink-0`/`grid` 混用）导致上半部高度失控 → 用户反馈"元素超出背景容器边界"。
2. **结构修复**：对齐真实 HeroDetailModal 骨架（主体 `flex-1` 层 + 上半 `grid shrink-0` + 下半 `h-[125px] shrink-0`）；装备/技能框保持 `w-15`（3 个 60px 框已占满列高预算），放大框内图标而非框本身；头像 A `w-18` / B·C `w-20`。用户反馈"B 感觉最好，但底部边框被裁"。
3. **垂直预算微调**：下半部 `h-[125px]→h-[112px]`、按钮 `py-2→py-1`、右列碎片行紧凑 → 底部边框完整。
4. **属性项拥挤修复**：属性面板 3 行每行需 22px 但只剩 18px → 属性项 `py-1→py-0.5` + `leading-tight`、`gap-1.5→gap-2`。用户最终选定 **C**（"非常完美，非常紧凑"）。

**关键设计约束发现**：容器 460px 定高（`max-h-[68vh]`），三列内容区约 240px——**放大是有垂直预算的**：放大字号/图标必须从间距或某区块挤出空间（下半部、按钮 padding、属性项 padding）。这解释了真实界面元素偏小的原因（定高容器逼的），也决定了后续放大规格的边界。

## 选定规格（变体 C，已折入真实 `HeroDetailModal`）

- 字号阶梯：正文/数值/按钮 `text-[11px]` · 标签 `text-[10px]` · 辅助小字 `text-[9px]`（装备名/技能名保持 8.5px、强化角标 7.5px）
- 图标：装备/技能框内 `w-7 h-7` · 属性项图标 `w-4.5 h-4.5` · 按钮内图标 `w-4`
- 头像：`w-20 h-20`（原 w-18）
- 按钮：统一 `py-1`
- 下半部：`h-[112px]`（原 125）· 属性项 `py-0.5` + `gap-2` + `leading-tight`
- 碎片行：`text-[7.5px]`（不随规格放大）
