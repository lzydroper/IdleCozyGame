# 05 — ADR-0020 与领域模型术语更新

Type: domain-modeling
Status: resolved
Blocked by: 01, 02, 03, 04

## Question

如何立项 ADR-0020 并更新 `CONTEXT.md` 术语，确立“挂机战斗离线暂停与体力解耦”的新架构决策，并严格限制范围避免蔓延？

具体需要决策：
1. `CONTEXT.md` 中的「离线挂机 (Offline Idle)」术语定义修订：
   - 明确指出“挂机战斗在离线期间暂停计算、重新上线时继续流程；在线期间持续循环推进”。
   - 明确避难所（发电机/回收站/流水线）、温室（生长/收割）、挂机远征与体力恢复**依然保持离线推进**。
2. 编写 ADR-0020 规格：《ADR-0020 挂机战斗离线暂停与体力解耦》：
   - 记录对 ADR-0002 确认式离线挂机推进条款的正式废止与反转。
   - 记录体力解耦模型与纯函数对外 API 决策。
   - 记录挂机战斗本地独占保存与云端排除策略。
   - 记录受影响模块清单（`offline.ts`, `levelCombat.ts`, `stamina.ts`, `persistence.ts`, `App.tsx` 等）与冗余配置清理方案（如 `maxIdleSettlementSeconds`）。

## Answer

1. **`CONTEXT.md` 术语更新**：
   - 将「离线挂机 (Offline Idle)」修订为：玩家在某关卡开启后，在线期间持续循环推进（单场满状态快照、即时结算与掉落）；离线期间挂机战斗暂停计算，重新上线时无缝继续。
   - 补充 Note：仅挂机战斗在离线期间暂停，避难所设施、温室作物、远征拾荒与体力恢复依然严格保持离线推进。
2. **立项 ADR-0020《挂机战斗离线暂停与体力解耦》**：
   - 正式在 `docs/adr/0020-offline-combat-pause-and-stamina-decoupling.md` 记录决策变更：
     - 反转 ADR-0002 的离线挂机推进条款，改为离线暂停、在线循环。
     - 确立避难所/温室/远征/体力的离线推进保全边界。
     - 确立 `src/state/stamina.ts` 独立纯函数服务接口。
     - 确立 `combat.idle` 本地独占存储与云端上传置空清洗。
     - 梳理受影响代码面与冗余配置清理清单。
